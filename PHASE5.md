# Phase 5 — MentorOS as an Android app (TWA)

Decided by a 3-agent council (mobile-engineering / product-premium / release-reality),
4 Jul 2026. Full reasoning summarized here; this file is the runbook.

## The decision

Wrap the **existing live PWA** into an Android app using a **Trusted Web Activity (TWA)**,
generated by **PWABuilder's cloud build**. Reasons:

- **Your web app stays the only codebase.** The Android app is a thin shell that loads
  `https://mentoros-c4ht.onrender.com`. Fix a bug → push to GitHub → Render redeploys →
  the app updates instantly, no store resubmission. Everything already built (push
  notifications, Gemini, Mongo, the whole UI) works unchanged.
- **PWABuilder builds it in the cloud**, so the fact that this machine has no Node.js /
  Android Studio / JDK does not matter.
- Capacitor and a native (Kotlin/React Native) rewrite were both rejected — Capacitor
  needs the toolchain we don't have, and native means two codebases forever.

## The gate is your phone, NOT a public listing

A brand-new personal Google Play account **cannot publish publicly** until it runs a
closed test with **12 testers opted in for 14 continuous days**, plus a **$25 fee** and
**ID verification**. That's ~3 weeks and needs 12 real people — a trap for a solo app.

**So: get the app on your phone by sideloading, start your 50 days, and treat the public
Play Store listing as a separate optional project later.** Don't let the store block studying.

## What's already done in the repo (server side is ready)

- `/.well-known/assetlinks.json` — a route that emits the Digital Asset Links file. It
  reads the fingerprint from an env var, so it returns `[]` (harmless) until you set it,
  then serves the real file with no code change. *(app.py)*
- `/healthz` — a tiny endpoint for an uptime pinger to keep Render warm. *(app.py)*
- `/privacy` — a real privacy-policy page (covers Gemini + MongoDB + how to delete data).
  This is the Privacy Policy URL Google asks for. *(public/privacy.html)*
- **Offline fallback** — `public/offline.html` + a safe service-worker upgrade. It only
  touches full page loads and is network-first, so it can NEVER serve stale JS (the old
  deploy footgun). A dead network now shows a branded "You're offline" page, not a crash.
- Manifest completed with `id` / `scope` / `categories` (PWABuilder reads these).
- The service worker now registers on load, so offline + push work in the installed app.

## What YOU (Faiz) do — Part A: get it on your phone (free, ~30 min)

1. **Keep the server warm first** (so the app doesn't open to a 30-60s blank screen):
   go to **uptimerobot.com** (free), make an HTTP monitor pointing at
   `https://mentoros-c4ht.onrender.com/healthz`, interval **5 minutes**.
   *(Note: this keeps the free instance running more, which uses more of the monthly
   free hours — fine for one app. If it ever gets annoying, Render's ~$7/mo tier removes
   cold starts entirely.)*
2. Open **pwabuilder.com** in Chrome. Enter `https://mentoros-c4ht.onrender.com`, let it
   score the PWA, then **Package for stores → Android → Download**.
3. **Keep the downloaded zip safe — it contains your signing keystore + passwords.** If you
   lose it you can't update the app later (unless Play App Signing is on — see Part B).
4. In that zip there's an `assetlinks.json` and a readme with a **SHA-256 fingerprint**.
   Paste that fingerprint to me (Claude) and tell me the package name PWABuilder used —
   I'll set it and the URL-bar disappears. *(Or set `ANDROID_CERT_SHA256` and
   `ANDROID_PACKAGE_NAME` in Render → Environment yourself.)*
5. The zip includes a **test APK**. Copy it to your Android phone, enable "install unknown
   apps" for your file manager, tap it, install. **MentorOS is now on your phone → start Day 1.**

## What YOU do — Part B: public Play Store listing (optional, later)

Only if you want it publicly searchable. Everything in Part A already works without this.

1. Pay **$25**, create a personal developer account, pass **ID + address verification**,
   turn on 2-Step Verification. (Card name must match your ID; no prepaid cards.)
2. In Play Console, create the app, upload the **AAB** from PWABuilder, opt into
   **Play App Signing** (recommended — lets Google recover your key if lost).
3. Play Console → App integrity shows **Google's** re-signing SHA-256. Give me that too —
   both fingerprints go in `assetlinks.json` (this is the #1 cause of a URL bar in
   production builds).
4. Fill the **Data safety** form (declare: user text sent to Google Gemini; state stored in
   MongoDB; encrypted in transit) and **Content rating** (Everyone). Attach the privacy URL
   `https://mentoros-c4ht.onrender.com/privacy`.
5. Add store assets: I can generate the 512 icon / 1024×500 feature graphic / screenshots
   when you're ready.
6. Recruit **12 testers**, run **Closed testing for 14 continuous days**, then request
   production. (You can add yourself + friends up to 100 on the internal track for instant,
   auto-updating installs meanwhile — that's the nicer middle ground if sideloading gets old.)

## After Phase 5 — the roadmap from here

Phase 5 is packaging, not new product. Once you're studying on the phone, the honest
next-steps, in priority order:

1. **Activate notifications** (already built, pending your Render env vars: `VAPID_PUBLIC_KEY`,
   `VAPID_PRIVATE_KEY`, `VAPID_CLAIMS_EMAIL`, `CRON_SECRET`) — reminders only matter once
   it's an app you actually open daily.
2. **Dogfood feedback loop** — you using it for real 50 days is the best product input; fix
   what annoys you, cut what you skip.
3. **Multi-user architecture** — the one real rebuild (per-user identity + concurrency-safe
   writes). Only needed if anyone besides you uses it. Flagged in AUDIT.md, not urgent.
4. **New app logo** (you asked to be reminded).
